Problem Statement

Across all screens, Sales Ops CRM currently exposes too many capabilities on the first viewport. The product reads as a dense technical dashboard rather than a focused operational tool. This plan defines — concretely — what stays visible, what moves behind progressive disclosure, and what is hidden by role. The governing principle: each screen has one primary job.

Scope
12 screens · App Shell through Executive Dashboard · all roles
Environment
LOCAL PILOT · desktop-first at 1440px · keyboard & mouse primary
Disclosure Primitives
Right drawer · centered modal · collapsed accordion · contextual side panel · detail drilldown page
10 Global UX Rules — apply to every screen
01
Overview screens show: list, 3–5 key metrics, filters, next obvious action. Nothing else on load.
02
Detail screens show: record summary (name, status, key numbers) + primary actions. Secondary fields on scroll or tab.
03
Multi-step workflows live in drawers or modals — not inline as stacked page sections.
04
Audit log, change history, and system events are collapsed by default behind an "Activity" accordion.
05
Admin metadata, field IDs, sync status, and debug info are hidden unless the user opens "Admin details".
06
Role-specific actions are only rendered when the current session role matches. No grayed-out inaccessible buttons.
07
Right-side context panels show a preview only (summary, quick facts). Full detail always opens in a drawer.
08
Tables show max 6 columns by default. Column chooser available in a popover. Dense mode opt-in per user.
09
Empty states show one action only: the next step the user should take. No product feature descriptions.
10
No nested cards. No "everything dashboard" panels. One level of nesting max: page → card/panel.
01
App Shell / Navigation
Primary job: orient the user by role and surface the most important pending item.
Rep Approver Manager Admin Exec
●
Visible by default
Brand mark + product name only (no tagline)
Tenant name + LOCAL PILOT badge
Role-filtered navigation — only sections the current role can access are rendered; no disabled/grayed items
Active section highlighted; unread badge count on Inbox and Approvals items only
User avatar + role label at bottom of sidebar
Global search bar in top bar (always visible)
▶
Move to drawer / modal
Role switcher → popover triggered from user block (only show when user has multiple roles)
User settings / preferences → right drawer from avatar
Keyboard shortcuts reference → modal via ? key
▼
Collapsed by default
Sub-navigation groups (e.g., "Admin" section) — collapsed until opened; state persisted per session
Environment/tenant selector (only relevant in multi-tenant setups)
✕
Role-hidden
Metadata Admin nav item — hidden for Rep, Approver, Exec
Import / Export nav item — hidden for Rep, Approver, Exec
Duplicate Review nav item — hidden for Rep, Exec
Executive Dashboard nav item — hidden for Rep, Approver
Primary CTA
+ New Opportunity Rep only
Secondary actions
Global search (⌘K) Notification bell
02
Sales Rep Workspace
Primary job: show the rep their open opportunities and what needs action today.
Rep
●
Visible by default
Current problem: KPI strip (5 metrics) + saved views row + 7-column filter bar + table + 380px right panel all shown simultaneously. First viewport is overwhelmed.
3 metrics max in a compact strip: Open Opportunities, Total Pipeline Value, Pending Approvals
Remove: avg deal size, win rate — not actionable from this screen
Saved views as pill tabs (My Queue, All Active, Needs Attention)
Search field + Stage filter + Owner filter — 3 controls maximum
Opportunity table: Name, Account, Stage (pip), Value, Approval Status, Last Updated — 6 columns max
Right panel: collapsed by default; opens as a 320px inline preview when a row is clicked
▶
Move to drawer / modal
Advanced filters (Close date range, Amount range, Product type, Region) → "More filters" popover
Bulk actions (reassign, export, archive) → appear in a toolbar above table only when rows are selected
Column chooser → popover from table header menu
Create new opportunity → right drawer (not a new page)
▼
Collapsed by default
Closed / Lost opportunities — separate "Closed" saved view, not shown in default list
System IDs, CRM sync status fields — accessible via column chooser
✕
Role-hidden
Team/owner filter — hidden for reps who can only see their own records
Export all / admin controls — hidden; Rep can export own records only from overflow menu
Primary CTA
+ New Opportunity
Secondary actions
Save current view Export (own records) Refresh
03
Opportunity Detail
Primary job: show the rep the status of one deal and let them take the next action (edit, advance stage, or submit for approval).
RepManager
●
Visible by default
Current problem: 1,945-line file. Inline stage-move validation panel (stagepop), 5-column snapshot grid, 360px right panel with stacked panels — all shown at once. The screen has at least 4 competing focal points.
Header row: Opportunity name, Account link, current Stage pill, Approval Status pill, Close Date, ARR value
Stage progress bar: horizontal stepper — compact, single row, no inline validation panel by default
Tab bar below header: Overview · Line Items · Contacts · Documents · Activity
Only Overview tab is open on load
Overview tab content: Deal snapshot (5–6 key fields in 2-column grid) + Approval chain summary (status only, not full history)
▶
Move to drawer / modal
Stage advance confirmation + validation checklist → modal (not inline stagepop)
Edit opportunity fields → right drawer (680px)
Submit for approval → opens Submit Approval drawer (screen 04 becomes a drawer, not a separate page)
Full approval history → "View approval history" link opens right drawer
Related contacts detail, document upload → via their respective tabs
▼
Collapsed by default
Activity log → "Activity" tab, collapsed accordion within it
System metadata (record ID, created by, source, sync status) → collapsed "System info" section at page bottom
Custom fields not mapped to core workflow → collapsed "Additional fields" accordion in Overview tab
✕
Role-hidden
Approval routing config, rule override options → hidden for Rep; visible for Manager only
Delete opportunity → hidden for Rep; Manager/Admin only, behind overflow menu
Primary CTA
Submit for Approval
Context-sensitive: changes to "Advance Stage" or "Edit" when approval is not the next step
Secondary actions
Edit Clone Add note ⋯ More
04
Submit Approval Flow
Primary job: let the rep configure and submit one approval request with minimum friction.
Rep
●
Visible by default
Current problem: 1,542-line page. The entire flow is inline: 4-step process strip + 5-column opportunity snapshot + 4-option request type selector + full form grid + urgency row + right rail + submit bar — all visible simultaneously. This is a wizard that became a wall.
Redesign as a right drawer (680px) triggered from Opportunity Detail. The drawer is the submission surface — no separate full page.
Drawer step 1 — Request type: 4 type cards (full width in drawer). Opportunity name + ARR shown as a compact header, not a full snapshot grid.
Drawer step 2 — Form: Only required fields visible by default. Urgency selector inline. Justification textarea at bottom.
Drawer step 3 — Review: Summary of what will be submitted. Routing chain preview (who will approve). Submit button.
Step indicator: simple 3-step pill strip at the top of the drawer — not a full-width arrow-process strip
▶
Move to drawer / modal
Full approval routing logic explanation → "How is routing determined?" link → small informational modal
Optional fields (attachments, secondary reviewers, CC list) → "Advanced options" collapsible at bottom of Step 2
▼
Collapsed by default
Policy warnings and validation details → shown inline only for fields that fail validation, not pre-emptively
Opportunity field details (all 5 snapshot columns) → collapsed; only Name + ARR shown in drawer header
✕
Role-hidden
Override routing / bypass approver — hidden for Rep; Admin-only
Request on behalf of another rep — hidden for Rep; Manager/Admin only
Primary CTA (per step)
Continue →
Step 3: "Submit for Approval" (filled primary button). Not available until all required fields are valid.
Secondary actions
← Back Save draft Cancel
05
Approver Inbox
Primary job: let the approver see what needs a decision and act on it immediately.
Approver
●
Visible by default
Current problem: 5 KPI metrics + 6 saved view tabs + 7-column filter row + table + 400px right panel — all visible on load. The approver's actual job (decide on a request) is buried under analytics.
2 metrics only: Pending (with overdue count highlighted) and Decided Today — shown as a compact 2-cell strip, not a 5-KPI dashboard
Queue tabs: Pending · Overdue · Decided (today) — 3 tabs, not 6 saved views
Filters: Search + Request Type + Submitted Date — 3 controls. "More filters" popover for the rest.
Table columns: Request name, Requester, Type, Amount, SLA countdown, Status — 6 columns max
Clicking a row opens Approval Decision Detail (screen 06) inline as a right drawer — not a navigation away from the inbox
▶
Move to drawer / modal
Advanced filters (region, product line, owner, date range) → "More filters" popover
Bulk decide (approve / reject multiple) → bulk action toolbar appears when rows are selected
Inbox settings (notification prefs, delegate) → gear icon → right drawer
▼
Collapsed by default
Locked / delegated items — visible only in a "Locked" filter tab, not in default Pending view
Historical decisions (older than today) → "All decided" tab with date grouping
✕
Role-hidden
Requests assigned to other approvers — not shown unless the user is also a manager with delegation access
Win rate / pipeline analytics metrics — not an approver concern; move to Manager / Exec dashboards
Primary CTA
Open & Decide
Opens drawer with Approval Decision Detail inline — approver never leaves the inbox
Secondary actions
Delegate selected Export decisions
06
Approval Decision Detail
Primary job: show the approver exactly what they need to make a decision — and nothing more.
Approver
●
Visible by default
Current problem: The screen is built as a full page with its own navigation, header strip, accbox, and multiple stacked panels. Opening it breaks the approver's inbox context entirely.
Redesign as a right drawer (720px) that opens from the Approver Inbox without page navigation
Drawer header: Request ID, type tag, requester name, submitted date, SLA countdown pill
Request summary: Type, Amount, Justification text, linked Opportunity name (clickable)
Approval chain: compact visual showing completed steps (✓) and current step (→). Only current approver's position highlighted.
Decision area: Approve / Reject / Send Back — always visible at the bottom of the drawer, sticky
Comment field: shown inline above decision buttons, required on Reject and Send Back
▶
Move to drawer / modal
Full opportunity detail → "View opportunity →" link navigates to screen 03 (opens in new tab or full nav)
Full audit trail of this request → "Request history" expandable section at bottom of drawer
Supporting documents → "Attachments" section, collapsed by default
▼
Collapsed by default
Previous approver comments — collapsed under "Approval chain" section; expand to read
Policy details and rule explanations — collapsed; "Why does this require approval?" expandable
✕
Role-hidden
Routing rule config / override — hidden; Admin-only
Reassign to another approver — hidden for standard approver; Manager/Admin only
Primary CTA
Approve
Secondary actions
Reject Send Back Delegate

08
Manager Pipeline
Primary job: let the manager scan their team's pipeline, identify risk, and act on individual deals.
Manager
●
Visible by default
Current problem: React-based, 356px side panel visible immediately on load. Filter bar has too many dropdowns. Table footer shows totals but those numbers aren't explained.
3 KPIs: Total Pipeline, At Risk (overdue SLA or stalled stage), Closing This Quarter
View toggle: Table (default) · Board (kanban by stage)
Filters: Owner (rep selector) + Stage + Close quarter — 3 controls; "More" popover for the rest
Table: Rep name, Opportunity, Account, Stage pip, Value, SLA status, Days in stage — 7 columns max (stage pip counts as 1)
Side panel: hidden by default; slides in from right when a row is clicked (360px preview)
▶
Move to drawer / modal
Opportunity detail → right drawer (manager read + comment; not a full page nav from pipeline view)
Reassign rep → modal from overflow menu on table row
Export pipeline → modal with format + date range options
Forecast editor → right drawer from "Edit forecast" button (not inline table cells)
▼
Collapsed by default
Closed / Won deals — separate "Closed" view tab
Individual rep totals in table footer — shown only when "Group by rep" view is active
✕
Role-hidden
Cross-team / org-wide pipeline — hidden; Manager sees own team only; VP+ sees org-wide in Exec Dashboard
Admin metadata columns — hidden
Primary CTA
Review At-Risk Deals
Filters table to at-risk items on click; removes itself when no at-risk items exist
Secondary actions
Edit forecast Export View: Table / Board

11
Duplicate Review / Merge
Primary job: let the admin identify and resolve duplicate records efficiently.
Admin
●
Visible by default
Duplicate groups list: each row = one group of N duplicate records with a confidence score and record count
Object filter: Accounts · Contacts — defaults to Accounts
3 metrics: Total duplicate groups, Records affected, Auto-resolvable
Group confidence score shown as a simple HIGH / MED / LOW tag — not a raw decimal number
▶
Move to drawer / modal
Merge decision UI (field-by-field winner selection) → right drawer (this is the primary interaction; do not show inline in list)
Bulk auto-resolve → confirmation modal before executing
Dismiss / mark as not duplicate → confirm modal
▼
Collapsed by default
Resolved / dismissed groups — separate "Resolved" tab, not visible by default
Match rule details (which fields triggered the match) → collapsed inside merge drawer
✕
Role-hidden
Entire screen — hidden from all non-Admin roles (account detail shows a warning banner + link to this screen)
Primary CTA
Review & Merge
Opens merge drawer for selected group
Secondary actions
Auto-resolve all HIGH Dismiss selected
12
Executive Dashboard
Primary job: give the exec a read-only health check of pipeline, approvals, and team performance at a glance.
ExecManager
●
Visible by default
Current problem: 4 KPIs + multiple chart panels + a 300px side panel + drill-down table — all visible on load. The dashboard tries to be both a summary and an operations tool simultaneously.
4 KPIs (keep, these work): Total Pipeline, Approval Cycle Time avg, Win Rate, Deals Closing This Quarter
2 charts only: Pipeline by Stage (funnel) · Approval Cycle Time trend (sparkline) — placed side by side
One focused table: Top 10 deals by value — Name, Rep, Stage, Value, Close Date. No other tables on first load.
Time period filter at top right: This Quarter / Last Quarter / This Year — single selector
▶
Move to drawer / modal
KPI drilldown (clicking a KPI tile) → right drawer with expanded chart + supporting table
Deal row click → read-only opportunity detail drawer (exec cannot edit)
Export dashboard as PDF / data export → modal
▼
Collapsed by default
Rep performance breakdown — collapsed "By rep" section below main table
Approval bottleneck analysis — collapsed "Approval health" section
Historical comparisons (QoQ, YoY) — collapsed inside KPI drilldown drawer
✕
Role-hidden
Any edit / submit / approve action — exec dashboard is entirely read-only
Admin metadata columns, system IDs — never shown on exec screen
Manager-level detail (individual rep quotas, day-by-day activity) — hidden; accessible from Manager Pipeline
Primary CTA
None — dashboard is read-only. No primary action button.
Secondary actions
Export PDF Refresh Time period selector
